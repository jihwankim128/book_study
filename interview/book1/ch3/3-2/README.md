# 프로세스와 스레드

* 포그라운드 프로세스(foreground process): 사용자와 상호작용하며 실행되는 프로세스
* 백그라운드 프로세스(background process): 사용자가 보지 못하는 곳에서 실행되는 프로세스
* 데몬 (demon): 사용자와 상호작용 없이 실행만되는 백그라운드 프로세스
  * Windows 에서는 Service 개념

## 메모리 영역 

* 커널 영역과 사용자 영역으로 구분된다.
* 커널 영역에는 프로세스 제어 블록(PCB) 정보가 저장된다.

### 사용자 영역

> *정적 할당 영역*: 실행 도중 크기가 변하지 않는 영역

* *코드 영역 (Code segment)*: 실행 가능한 명령어가 저장되는 공간
  * 읽기 전용으로 텍스트 영역이라고도 부른다.
* *데이터 영역 (Data segment)*: 프로그램이 실행 시간 동안 데이터가 저장되는 공간
  * 정적 변수, 전역 변수가 대표적으로 저장된다. 
  * BSS 영역도 구분하는 경우가 있다.
    * BSS 영역은 초기화 되지 않은 데이터(변수)를 저장한다.

> *동적 할당 영역*: 크기가 변할 수 있는 영역

* *힙 영역 (Heap Segment)*: 사용자(개발자)가 직접 할당 가능한 공간
  * 사용 가능한 메모리 공간이다.
  * 메모리 누수(Memory Leak) 문제로 사용했으면 메모리를 반환해야한다.
    * 일부 프로그래밍 언어는 자체적으로 관리하는 가비지 컬렉션(Garbage Collection) 기능을 제공한다.
* *스택 영역 (Stack Segment)*: 일시적으로 사용할 값들이 저장되는 공간
  * 매개 변수, 지역 변수, 함수 복귀 주소 등이 저장된다.
  * 스택 트레이스(stack trace) 형식으로 디버깅에 사용할 수 있다.

### PCB

* *PCB(Process Control Block)*: 프로세스를 식별할 수 있는 정보 
  * 프로세스 관련 다양한 정보를 포함한 구조체
  * 프로세스를 메모리에 적재 시 PCB가 커널 영역에 생성
  * 프로세스 종료 시 메모리에서 PCB 폐기
  * 프로세스 ID, 실행 중 레지스터 값, 프로세스 상태, CPU 스케쥴링 정보, 메모리 정보, 파일 입출력 정보
  * 커널 내 PT(Process Table)을 통해 관리되는 경우가 많다.
    * 메모리 내 논리적인 영역
    * 좀비 프로세스(zombie Process): 프로세스가 비정상 종료될 경우 PT에 종료된 프로세스 PCB 정보가 남아있는 경우

### 문맥 교환 (Context Switching)

* 실행중인 프로세스(운영체제에 의해 CPU의 자원을 할당받은 프로세스)들은 CPU에 의해 번갈아가며 실행된다.
* 프로세스들은 타이머 인터럽트(timer interrupt, timeout interrupt)에 의해 CPU 사용시간이 제한된다.
* 이 때, 사용시간이 제한되며 현재까지의 프로세스 정보를 백업해야하는데, 이 정보를 문맥이라고 한다.
* 즉, PCB에 현재 프로세스의 문맥을 백업하고 다음 실행할 프로세스의 문맥을 복구하는 것을 *문맥 교환*이라고 한다.
  * 너무 잦은 컨텍스트 스위칭은 캐시 미스가 발생이 높아지고 오버헤드로 이어질 수 있다.

### 프로세스의 상태

* 생성 상태 (new)
  * 프로세스를 생성중인 상태, 메모리에 적재되어 PCB를 할당 받은 상태, 실행할 준비가 완료됨
* 준비 상태 (ready)
  * CPU의 할당을 받을 때까지 대기하는 상태, 실행 상태로 전환되는 것을 디스패치(dispatch)라고 한다.
    * time intterupt 로 인해 자신이 실행 될 때까지 대기
* 실행 상태 (running)
  * 준비 상태에서 dispatch 되면서 일정 시간 동안 CPU 사용이 가능한 상태
    * time interrupt로 인해 닫시 준비 상태로 돌아갈 수 있다.
    * 입출력 요청 등에 의해 대기 상태로 전환되고 i/o interrupt가 발생할 때까지 대기한다
* 대기 상태 (blocked)
  * I/O 작업, 자원 대기 등 당장 실행이 불가능한 조건일 경우 대기 상태가 된다.
    * 대표적인 케이스는 I/O
  * 다시 실행이 가능해지면 준비 상태로 돌아간다.
  * 블로킹 I/O와 논블로킹 I/O 가 존재한다.
* 종료 상태 (terminated)
  * 프로세스가 종료된 상태로 OS는 PCB와 메모리를 정리

## 멀티프로세스와 멀티스레드 

* 멀티 프로세스(multi-process): 동시에 여러 프로세스가 실행
  * 각 각의 프로세스가 영향을 끼칠 수 없고 PID가 다름
* 멀티 스레드 (multi-thread): 한 프로세스의 코드를 동시에 실행
  * 멀티 프로세스와 차이점: 자원의 공유 여부
  * 멀티 스레드는 자원을 공유, 프로세스는 공유 X
* 스레드 join
  * 생성한 주체가 join 된 스레드가 종료할 때까지 대기하는 것

## 프로세스 간 통신 (IPC, Inter-Process Communication)

* 자원을 공유하지 않음에도 자원을 공유하는 방법
* 공유 메모리
  * 데이터를 주고 받는 프로세스 간 공통적으로 사용할 메모리 영역을 토대로 데이터를 주고 받는 방식
  * 메모리 영역, 공유 변수, 파일 등을 활용해 마치 각 프로세스는 자신의 메모리 영역을 쓰고 읽는 것처럼 통신
    * 커널 영역의 개입이 거의 없고, 통신 속도가 빠름
  * 데이터의 일관성이 훼손되는 레이스 컨디션이 발생
* 메세지 전달
  * 프로세스 간 주고받을 데이터를 메시지의 형태로 주고 받는 방식
  * send(), recv()라는 시스템 콜을 호출해, 프로세스 간 메시지를 송수신한다.
    * 커널을 활욜하므로 공유 메모리보다는 느리다.
  * 파이프: 프로세스 간 단방향 통신도구
    * A에서 쓰면 B가 읽는 방식, 양방향으로 통신할 경우 2개의 파이프 필요
    * 익명 파이프(unnamed pipe): 부모와 자식 프로세스 간 통신이 가능한, 단방향 방식
    * 지명 파이프(named pipe): 다른 프로세스 간 통신 가능한, 양방향 방식 (익명 파이프 확장 - FIFO)
  * 시그널: 신호를 통해 비동기적으로 이벤트 발생을 알림
    * IPC 개념이 아니라 프로세스 개념인데, IPC에서도 활용 가능
    * 시그널 발생 시 프로세스를 잠시 중단하고 시그널 핸들러를 실행
    * 프로세스는 직접 시그널을 발생 시킬 수 있고, 시그널 핸들러는 (재)정의 할 수 있다.
    * IPC 개념이 아니라면 대부분 프로세스 종료, 무시, 코어 덤프를 생성한다.
    * 코어 덤프란 OS에서 작업하던 메모리 상태가 기록되는 정보
  * 원격 프로시저 호출(RPC), 소켓도 존재
