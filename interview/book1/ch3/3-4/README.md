# CPU 스케줄링

* CPU 스케줄링: 운영체제의 CPU 배분 방법
* CPU 스케줄링 알고리즘: 스케줄링 절차
* CPU 스케줄러: CPU 스케줄링 알고리즘을 결정하고 수행하는 OS의 일부분

### 우선순위

* 프로세스 별 우선순위를 PCB에 명시
  * 우선순위가 높은 프로세스에 CPU 자원을 더 빨리, 많이 할당
  * 사용자가 우선순위를 직접 높일 수 있음
* CPU 활용률(CPU Utilization)이 높을 수록 우선순위가 높음 
* CPU Burst: 프로세스가 cpu를 이용하는 작업
  * CPU Burst가 높은 프로세스 = CPU Bound Process
* IO Burst: 입출력 장치를 기다리는 작업
  * IO Burst가 높은 프로세스 = IO Bound Process
* IO Bound Process를 가능한 빨리 실행시키면, IO 대기 상태에 CPU Bound Process를 처리할 수 있다.
  * 그래서 IO Bound Process의 우선순위가 더 높다.

### 스케줄링 큐 (Scheduling Queue)

* 프로세스들은 스케줄링 큐에서 자원을 대기한다.
* 준비 큐(Ready Queue)와 대기 큐(Waiting Queue)로 구분된다.
  * 준비 큐는 CPU 자원 할당을 대기
  * 대기 큐는 대기 상태의 PCB가 대기

### 선점형 스케줄링과 비선점형 스케줄링

* 선점형 스케줄링(preemptive scheduling): 타이머 인터럽트 기반
  * OS가 프로세스로부터 CPU 자원을 강제로 빼앗아 다른 프로세스에 할당 할 수 있는 스케줄링
  * 급한 프로세스를 먼저 처리 할 수 있어, CPU 독점을 막을 수 있따.
    * 여러 프로세스에 골고루 자원 분배 가능
* 비선점형 스케줄링(non-preemptive scheduling)
  * 프로세스가 CPU를 사용하고 있을 때, 다른 프로세스가 끼어 들 수 없는 스케줄링
    * 컨텍스트 스위칭이 적어 오버헤드 발생이 적다.
    * CPU를 사용중인 프로세스가 있으면, 우선순위가 높은 프로세스는 대기해야된다.

## CPU 스케줄링 알고리즘

### 선입 선처리 스케줄링 (FCFS, First Come First Served)

* 삽입된 순서대로 스케줄링한다.
* 특정 프로세스들은 대기 시간이 매우 길어질 수 있다.
  * 호위 효과(convoy effect)
* 비선점

### 최단 작업 우선 스케줄링 (SJF, Shortest Job First)

* CPU 사용 기간이 가장 짧은 프로세스부터 실행
* 비선점

### 라운드 로빈 스케줄링 (Round robin)

* 타임 슬라이스(time slice) 개념이 도입 돼, CPU 사용 시간을 정해놓는다.
* 삽입된 순서대로 CPU를 이용하지만 time slice 만큼 이용
  * 한 time slice에 모든 작업이 끝나지 않으면 컨텍스트 스위칭이 발생
    * 큐의 맨 뒤로 이동
* 선점

### 최소 잔여 시간 우선 스케줄링 (SRT, Shortest Remaining Time)

* 최단 작업 우선 스케줄링과 라운드 로빈 스케줄링을 합친 방식
* 타임 슬라이스 만큼 CPU 이용 후, 남은 시간이 가장 적은 프로세스를 다음 작업으로 처리
* 선점

### 우선순위 스케줄링 (Priority)

* 우선순위를 부여해 가장 높은 우선순위의 프로세스부터 실행
* 가장 우선순위가 낮은 프로세스는 계속해서 실행이 연기 될 수 있다.
  * 아사 현상 (starvation)
  * 에이징(aging) 기법으로 방지 가능
    * 오래 대기한 프로세스의 우선순위를 점차 높임
* 선점

### 다단계 큐 스케줄링 (multilevel queue)

* 우선순위 스케줄링의 발전된 형태
* 우선순위 별로 여러 큐를 사용
* 우선순위 큐 별로 작업들을 먼저 실행
* 마찬가지로 아사 현상이 발생할 수 있음.
* 비선점

### 다단계 피드백 큐 스케줄링 (multilevel feedback queue)

* 다단계 큐 문제점을 해결한 방법
* 프로세스들이 큐 사이를 이동할 수 있다.
* 새로 진입하는 프로세스는 가장 높은 운선순위 -> 타임 슬라이스 동안 실행
* 타임 슬라이스 내 작업이 끝나지 않으면 다음 우선순위 큐로 이동
  * CPU Bound Process는 자연스레 후순위 처리가 됨
  * CPU 사용량이 적은 IO Bound Process는 자연스레 우선순위
* 결국 아사 현상이 발생할 수 있지만 에이징 기법을 적용할 수 있음.
  * 큐 간 프로세스 이동이 가능하기 때문, 우선순위가 낮아진 프로세스들은 자연스레 우선순위가 높아짐

## 리눅스 CPU 스케줄링

* 리눅스는 상황에 따라 다양한 스케줄링 알고리즘이 사용됨

> SCHED_FIFO, SCHED_RR

* RT(Real Time) 스케줄러에 의해 이뤄지는 스케줄링
* 실시간 프로세스에 적용되는 정책

> SCHED_NORMAL

* 일반적인 프로세스에 적용되는 정책
* CFS(Completely Fair Scheduler)에 의해 스케줄링
  * 완전히 공평한 CPU 시간 배분
* 리눅스는 프로세스마다 가상 실행 시간(virtual runtime, vruntime) 정보를 유지
  * CFS는 vruntime이 가장 작은 프로세스부터 스케줄링
    * 가중치를 고려한 값
    * RB 트리를 활용해 vruntime 최솟값을 꺼냄
