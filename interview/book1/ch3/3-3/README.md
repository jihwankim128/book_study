# 동기화와 교착 상태

* 공유 자원에 동시에 접근하는 경우 문제가 발생할 수 있다.
  * 이 때, 문제가 발생할 수 있는 코드를 *임계 구역(critical section)*이라고 한다.
* 공유자원을 처리하는 사이클 순서, 컨텍스트 스위칭으로 인해 데이터 일관성이 깨진다.
  * 여러 프로세스 혹은 여러 스레드가 동시에 임계 구역의 코드를 실행한 것
    * *레이스 컨디션(race condition)*
    * 해결하기 위해, 하나의 작업이 끝날 떄까지 다른 하나는 대기해야 됨.
* *동기화(synchronization)* 조건 
  * 실행 순서 제어: 프로세스 및 스레드를 올바른 순서로 실행
  * 상호 배제: 임계 구역에 하나의 프로세스 및 하나의 스레드만 접근

## 동기화 기법

### 뮤텍스 락 (mutex lock)

* 하나의 프로세스 및 스레드의 공유 자원 접근을 고려하는 동기화 도구
* mutex(MUTual Exclusion, 상호 배제): 상호 배제를 위한 잠금
  * 임계 구역에 접근하고자 하면 lock을 acquire 해야 한다.
  * 임계 구역의 작업이 끝났다면 lock을 release 해야 한다.

### 세마포 (Semaphore)

* 여러 프로세스 및 스레드의 공유 자원 접근을 고려하는 동기화 도구
* 이진 세마포도 존재하지만 이는 뮤텍스 락과 거의 동일
  * 카운팅 세마포로 이점 활용

### 모니터 (Monitor)

* 조건 변수(condition variable)
  * 실행 순서 제어를 위한 동기화 도구
  * 특정 조건 하에 프로세스나 스레드의 실행/일시 중단하며 순서를 제어 가능
  * 특정 프로세스가 실행도리 조건이 되지 않았을 때, wait()로 실행 중단
  * 특정 프로세스가 실행될 조건이 충족되었을 때, signal()을 통해 실행 재개
* 앞서 다른 동기화 기법은 임계 구역 접근에 대한 방법이었고, 모니터는 실행 순서 제어까지 동기화가 된다.
  * 공유 자원과 공유 자원을 다루는 함수로 구성

### 스레드 안전 (Thread Safety)

* 객체에 동시 접근이 이루어져도 실행에 문제가 없는 상태

## 교착 상태 (Deadlock)

* 발생하지 않을 상황을 기다리며 프로세스의 진행이 멈추는 상황

### 발생 조건

* 상호 배제: 임계 구역에 접근하지 못해서 대기함 - 점유와 대기 유발
* 점유와 대기: 자원을 할당 받은 상태에서 다른 자원을 할당 받기 위해 대기 - 비선점 유발
* 비선점: 다른 프로세스의 자원을 강제로 뺏지 못해서 대기 - 원형 대기 유발
* 원형 대기: 최종적으로 위 세가지 조건으로 각 프로세스가 서로 사이클이 발생 - 교착 상태

### 해결 방법

* 예방
  * 앞서 발생 조건은 결국 전파되는 것이라 발생 조건 중 한가지만 해결이 되면 된다.
  * 프로세스 별로 순서를 매기거나 한 프로세스에 자원을 몰아주면 된다.
    * 점유와 대기 혹은 원형 대기를 해결
* 회피
  * 교착 상태가 발생하지 않을 정도로 자원을 할당
* 검출 후 회복 
  * 교착 상태가 검출되면 자원 선점, 강제 종료 등으로 회복
