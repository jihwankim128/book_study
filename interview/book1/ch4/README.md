# 자료구조

## 시간 복잡도와 공간 복잡도 

* O(N)과 같은 형태로 시간 복잡도의 상한을 표현
* 공간복잡도: 프로그램 실행 시 필요한 메모리 자원의 양

## 배열과 연결 리스트

### 배열 

* 접근: O(1)
* 삽입: O(1), 재정렬 시 O(N)
* 삭제: O(N)
* 정적 배열과 동적 배열이 존재

### 연결 리스트

* 접근: O(N)
* 삽입, 삭제: O(N), 위치를 알 경우 O(1)
* singly, doubly, circular 가 존재

## 스택과 큐

### 스택

* 후입 선출
* 함수, URL 등에 적용 하는 예시가 있다

### 큐

* 선입 선출
* 버퍼에 주로 활용
* 원형 큐, 덱(양방향 큐), 우선순위 큐 등으로 변형해 사용도 함

## 해시 테이블

* 키와 값으로 이루어진 자료구조
  * 값은 버킷에 저장되어 있다.
  * 로드 팩터(load factor): 해시 테이블 데이터 수 / 버킷의 수
    * 로드 팩터가 클 수록 성능이 떨어짐
    * 하나의 버킷에 데이터가 많기 때문에 O(N) 탐색이 필요해짐

### 해시 함수

* 임의의 길이를 지닌 데이터를 고정된 길이의 데이터로 변환하는 단방향 함수
  * 해시 알고리즘을 통해 변환
  * SHA-1, 3, 256, 512, HMAC 등
* 모듈러 연산을 활용한 해시 함수
  * 키(k)를 해시 테이블 크기(m)으로 나눈 나머지를 해시 값으로 사용
  * k mod m -> 충돌 위험이 높음
* 많은 메모리 공간 vs 빠른 성능 (O(1))의 트레이드 오프

### 해시 충돌

* 해시 값이 같은 경우

> 체이닝

* 충돌이 발생한 해시 값의 데이터를 연결 리스트로 구성

> 개방 주소법 - 선형 조사

* 충돌이 발생한 경우 다음 버켓에 저장
* 군집화 현상이 발생 - 성능 저하
  * 이차 조사법으로 f(key) + n^2 으로 약간 완화가능
  * 근본적 해결 X

> 개방 주소법 - 이중 해싱

* 보조 해시 함수를 사용
* 충돌 발생시 f(key) + ng(key) 의 버켓에 저장
  * 대부분 군집화 완화

## 트리

### 순회 

* 전/중/후위 순회 (루트가 출력되는 순서에 따라)

### 종류

> BST (Binary Search Tree)

* 검색에 특화 O(log N), 편향 트리인 경우 O(n)
* 특정 노드의 왼쪽 서브 트리는 작은 값으로 구성, 오른쪽 서브 트리는 큰 값으로 구성

> Heap

* 최소, 최대 값 탐색에 특화 O(log N)
* 우선순위 큐 자료구조
* 부모 노드가 자식 노드보다 큰 값, 작은 값으로 구성됨

> RB Tree

* 자가 균형 트리 O(log N), AVL 트리도 있음
* RB 트리 조건: 루트 노드와 리프 노드는 블랙, 자식 노드는 레드
  * 루트 노드에서 임의의 리프 노트에 이르는 경로의 블랙 노드 수는 같아야 함
  * 리프 노드는 NIL 노드
* 새 노드 삽입 시 Red로 간주 (루트 노드는 Black으로 삽입)
  * 삽입후 RB 트리 조건에 부합할 경우 회전 및 색상 재지정이 발생
  * 트리의 회전: 양쪽 서브트리 높이의 균형을 맞추기 위한 방법
    * 부모 노드와 자식 노드의 관계를 재지정

> B Tree

* 다진 탐색 트리, 각 키들이 오름차순으로 저장되어 있음
  * M차 B트리에서 루트, 리프를 제외한 노드들은 최소 [M/2] 개의 자식을 가질 수 있음
* 모든 리프 노트드의 깊이가 같다.
  * 편향된 케이스 없음
* N개의 키 사이 사이 자식 노드가 존재함 -> 자식 노드의 수는 반드시 N+1개가 된다.
* 변형된 B+ Tree가 존재한다.
  * 실질적인 모든 데이터가 최하위 리프 노드에 위치
  * 최하위 리프 노드는 연결 리스트 형태로 처리
