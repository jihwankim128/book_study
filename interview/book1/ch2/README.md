# 컴퓨터 구조의 큰 그림

## 컴퓨터가 이해하는 정보와 핵심 부품

| 주제      | 하위 항목        | 설명                                              |
|---------|--------------|-------------------------------------------------|
| 데이터     | 정수           | 0과 1로 표현되는 숫자 중 소수점이 없는 형태                      |
| 데이터     | 실수           | 0과 1로 표현되는 숫자 중 소수점이 있는 형태                      |
| 데이터     | 문자           | 0과 1의 조합(문자 인코딩)으로 문자를 표현                       |
| 명령어     | 명령어의 종류      | 컴퓨터가 수행할 수 있는 연산, 제어 등의 종류                      |
| 명령어     | 명령어 사이클      | 명령어를 인출(Fetch), 해석(Decode), 실행(Execute)하는 과정    |
| CPU     | 주요 구성 요소     | 제어장치, 연산장치, 레지스터 등                              |
| CPU     | 빠른 명령어 처리 기술 | 파이프라이닝, 슈퍼스칼라, 분기 예측 등                          |
| 메모리와 캐시 | RAM          | 휘발성 메모리, 프로그램 실행 중 데이터를 임시 저장                   |
| 메모리와 캐시 | 엔디안          | 메모리에 데이터가 저장되는 순서 (빅엔디안, 리틀엔디안)                 |
| 메모리와 캐시 | 캐시 메모리       | CPU와 메모리 간 속도 차이를 줄이기 위해 사용하는 고속 메모리            |
| 보조기억장치  | RAID 기법      | 여러 디스크를 결합해 성능·안정성을 높이는 기술                      |
| 입출력장치   | 입출력 기법       | 프로그램 입출력, 인터럽트 입출력, DMA(Direct Memory Access) 등 |

## 컴퓨터가 이해하는 정보

### 소수 표현하기
* 소수에서 부동 소수점(floating point) 표현 방식을 사용 (IEEE 754)
  * 정밀도의 한계가 존재하므로 오차가 발생
  * 지수와 가수(소수 부분)로 구분
  * 32bit: 1bit(부호) + 8bit(지수) + 23bit(가수) + bias(127)
  * 64bit: 1bit(부호) + 8bit(지수) + 52bit(가수) + bias(1023)
  * 무한 소수의 경우 표현하는 bit의 제한으로 일부를 버림
    * 여기서 오차가 발생

### 문자 표현하기
* ASCII(8bit), EUC-KR(2byte)의 한계
* Unicode(2byte) 등장
  * 확장 가능한 가변 길이 인코딩 UTF-8, UTF-16, UTF-32을 사용
* base64 인코딩
  * 64bit 표현 방식
  * 문자 -> 2진수 변환 -> 6bit씩 끊음
  * 6bit씩 끊으면, 특정 문자열은 byte를 구성할 수 없게 됨.
    * 남는 공간은 0으로 다 채우며 패딩(padding) 발생
    * 패딩은 '='으로 인코딩 됨
* 명령어
  * 수행할 동작(연산코드) + 수행할 대상(오퍼랜드)으로 구성
  * 수행할 대상은 분기 처리를 위한 위치 이동(데이터가 저장된 위치), 연산을 위한 값(데이터 자체)가 됨
    * 특히 데이터가 저장된 위치가 많이 사용돼서 주소 필드(address field)라고도 부름
    * 메모리 접근이 추가적으로 발생함
  * 대표적인 연산 코드의 유형: 데이터 전송, 산술/논리 연산, 제어 흐름 변경, 입출력 제어
* 명령어 사이클
  * 메모리의 명령어를 CPU로 가져오는 인출 사이클(fetch)
  * 명령어를 실행하는 실행 사이클(execution)
  * 명령어의 구성에 따라 추가 메모리 접근이 필요한 경우 간접 사이클(indirect)
  * 인터럽트 사이클

## CPU

### 레지스터
* PC(IP): 다음 명령어 주소를 담음 (무조건 +1이 아님, stack-function)
* IR: ALU가 처리할 수 있도록 명령어를 저장해둠
* 범용 레지스터
* Flag: 부호, 제로, 캐리, 오버플로우, 인터럽트, 슈퍼바이저 플래그 등
* SP: Stack 영역의 데이터 위치를 가르키는 레지스터

### 인터럽트
* CPU의 작업을 방해하는 신호
* 동기 인터럽트 (synchronous): 예외, 코드 레벨
* 비동기 인터럽트 (asynchronous): 입출력 장치, 하드웨어 인터럽트
  * 하드웨어 작업 간 계속 대기할 수 없으므로 비동기 처리를 통해 알림 형식으로 처리
  * 인터럽트 플래그를 통해 인터럽트를 받아들일지 판단 가능
    * 막을 수 없는 인터럽트(non maskable interrupt)도 존재
  * 인터럽트 서비스 루틴 (ISR, Interrupt Service Routine)을 통해 인터럽트 처리
    * 인터럽트 핸들러라고도 부름.
    * 인터럽트를 어떻게 처리할 지 정보가 담겨 있는 프로그램
    * 인터럽트 서비스 처리 후 본래 작업으로 돌아옴.
    * 인터럽트 벡터를 통해 인터럽트 서비스 루틴의 시작 주소를 알게 되고, 각기 다른 인터럽트를 처리 가능
    * 기존 작업을 재개하기 위해 기존 내용은 스택 영역에 백업
  * 즉, 실행 사이클 중 인터럽트 신호가 발생하면 인터럽트 처리를 위한 인터럽트 사이클을 처리 후 다시 인출 사이클

### 예외
* 폴트
  * 예외가 발생한 명령어부터 재실행
  * 데이터 처리 중 HW 접근이 필요할 때, 인터럽트가 발생하면서 다시 재실행
  * 순차적으로 처리하므로 동기적
* 트랩
  * 예외가 발생한 다음 명령어부터 실행
  * 대표적으로 디버깅, 현재 디버깅 포인트를 확인하기 위해 일시 중단하는 인터럽트
  * 해당 명령어에 대해 디버깅이 끝나면 다음 명령어 처리 -> 동기적
* 중단
  * 프로그램 종료 오류
* SW 인터럽트
  * 시스템 콜

### CPU 성능 향상을 위한 설계

* 클럭 속도를 높이기 -> 처리량이 높아짐
  * 클럭 속도를 높이면 발열로 심각한 오류가 발생 -> 한계점 존재
* 멀티 코어와 멀티 스레드를 활용 (하드웨어적, 논리 프로세서)
  * 코어 수와 코어 내부 스레드 수를 늘리면서 병렬 처리 및 작업량 증가

### 파이프라이닝을 통한 명령어 병렬 처리

* 단일 CPU에서 성능을 향상시키기 위한 기법
  * CPU 명령어 사이클을 보면, 각 단계에서 다른 HW Unit들은 쉬고 있음
  * 하나의 명령어 사이클을 처리하면서 다른 명령어 사이클을 처리하며 놀고 있는 Hw Unit을 효과적으로 사용하는 방법
    * 처리량 증가
  * fetch, decode, execution, write back
  * 각 각의 과정을 명령어 파이프라인에 넣고 처리 (파이프라이닝)
* 단일 CPU에서 여러 명령어 파이프라인을 포함하도록 하는 슈퍼 스칼라가 등장
  * 하나의 CPU에 여러 CPU 내부 Unit이 존재
  * CISC
    * 하나의 명령어가 비규격화로 가변 길이라 적은 수의 명령어로 처리 가능
    * 다만 가변적이라 파이프라이닝 예측이 어려움
  * RISC
    * 하나의 명령어가 규격화 되어, 많은 수의 명령어가 필요
    * 규격화된 크기로 파이프라이닝 예측이 쉬움 (최적화 됨)
* 하자드
  * 데이터 하자드: 데이터 의존성
    * 이전 데이터에 대한 작업이 끝나야 다음 데이터가 작업이 되는 경우
    * 명령어 처리 (z = x + y)를 다음 명령어에서 z+y 등으로 사용할 때
    * 파이프라이닝이 제대로 동작하지 않을 수 있음
  * 제어 하자드: PC의 갑작스러운 변화 -> for, stack 등
    * 미리 인출한 명령어가 쓸모 없어지게 됨
  * 구조적 하자드: 서로 다른 명령어가 동시에 CPU 부품을 사용
    * 파이프라이닝 순서 처리 중 다른 하자드를 관리하면서 발생할 수 있음
    * 자원 위험이라고도 함.
  
## 메모리

### RAM
* 통상 RAM (Random Access Memory) -> 임의 접근(직접 접근)을 한다.
* DRAM - Dynamic
  * 시간이 지나면 저장된 데이터가 점차 사라짐
  * 재활성화가 필요하나 낮은 전력, 높은 집적도 등의 장점
  * 일반적인 메모리
* SRAM - static
  * 일반적인 캐시
  * DRAM과 반대되는 개념, 더 빠름
* SDRAM - Synchronous Dynamic
  * 클럭 신호와 동기화
  * 기존 DRAM은 CPU가 메모리에 접근할 때, 예측 시간을 추가했음.
    * 이정도면 DRAM에 도착하겠지?
  * 그래서 CPU 신호와 동기화해서 예측 시간을 없애고 빠르게 접근 가능
* DDR SDRAM - Double Data Rate
  * 대역폭을 넓힘
  * SDRAM에서 2배 넓힘
  * DDR2, 3, 4 -> 2^n 배 대역폭 넓힘

### 메모리에 바이트를 밀어넣는 방법

* 빅엔디안
  * MSB가 낮은 번지, LSB가 높은 번지
  * 마치 큐
* 리틀 엔디안
  * MSB가 높은 번지, LSB가 낮은 번지
  * Little -> LSB -> 낮다, LL낮
  * 마치 스택
* 일반적으로 전환이 되지만, 리틀 엔디안을 많이 씀

### 캐시 메모리

* SRAM 기반, CPU 코어와 가까운 대로 L1, L2, L3
* L1은 분리형 캐시로 Instruction만 저장하는 L1I, Data만 저장하는 L1D로 구분됨
* 참조지역성
  * 시간: 최근 접근했던 공간에 재접근한다
    * for문
  * 공간: 접근한 메모리 주변에 다시 접근할 가능성이 있다.
    * array
* 캐시 쓰기
  * 값 변경 시 메모리에 직접 변경하면 캐시는 그대로라서 데이터 일관성 문제가 발생
  * 직접 쓰기 write through
    * 캐시 메모리와 메모리에 둘 다 반영
    * 메모리에 추가 접근하는 문제 -> 자주 바뀐다면 성능 정하
  * 지연 쓰기 write back
    * 캐시 메모리에만 변경
    * 나중에 메모리에 반영 -> 일관성 위험, 대신 빠름
  * 그 외 다른 코어간 캐시 메모리의 일관성 문제도 존재

## 보조기억장치와 입출력 장치

### RAID 0
* 여러개의 보조기억장치에 데이터를 단순히 나누어 저장하는 구성 방식
* stripe: 여러 디스크 간 분산되어 저장된 데이터
* striping: 여러 디스크 간 부산하여 저장하는 것
* 하나의 기억 장치에서 여러 정보를 가져오는 것은 느리다.
  * 1초에 100개를 가져오는 것 vs 1초에 50개를 가져오는 것 4개로 병렬 = 1초에 200개
* 단점으로 저장된 정보가 안전하지 않다.
  * 디스크 중 하나에 문제가 발생하면, 전체에 문제가 생긴다.
  * 머리, 몸통, 다리가 있으면 머리와 몸통만 조합하는 느낌

### RAID 1
* 복사본을 만드는 Mirroring
* RAID 0 에서 4개로 구성한다고 가정
  * 2개는 RAID 0, 2개는 RAID 0 을 복사
  * 비용이 비싸지고, 그만큼 용량 낭비가 발생
  * 다만 안전
    * 하나의 RAID 0 에서 장애가 발생하면
    * 복사본에서 복구 가능 (가용성)

### RAID 4
* RAID 1처럼 완전한 복사본 대신, 패리티를 저장한 장치를 이용
  * 오류 검출, 오류 발견 시 복구
  * RAID 1는 2 by 2 striping 였음.
  * RAID 4는 3 striping + parity disk
    * RAID 1보다 성능 향상
  * 패리티는 본래 오류 검출용이지만, RAID 4에서는 복구 로직도 포함

### RAID 5
* RAID 4에서 three striping disk 가 병렬로 패리티 disk 에서 검사
  * parity disk deadlock
  * 4 striping 을 두고 각 disk 특정 stripe 에 패리티 검출 stripe 를 위치
    * 패리티도 분산하면서 RAID 4 병목을 해결
    
### RAID 6
* RAID 5 와 구성은 동일
* 패리티 stripe를 두 개 두면서 안전성을 더욱 높임.
  * 대신 새 정보마다 함께 저장하는 패리티가 두개이므로 RAID 4보다 성능이 조금 더 낮음
  
### Nested RAID
* 여러 RAID 레벨을 혼합한 방식
* RAID0 + RAID1 = RAID 10
* RAID0 + RAID5 = RAID 50

### 입출력 기법

* 모든 HW는 각자의 장치 컨트롤러로 컴퓨터 내부와 연결되어 정보를 주고 받는다.
* 장치 컨트롤러마다 장치 드라이버라는 프로그램으로 작동한다.
  * 장치 컨트롤러의 동작을 알고 컨트롤러가 컴퓨터 내부와 정보를 주고 받을 수 있도록 하는 것
* 인터럽트 기반 입출력
  * 우선순위 기반으로 인터럽트를 처리
    * 무시할 수 없는 인터럽트는 우선 순위가 높은 인터럽트
  * 프로그래머블 인터럽트 컨트롤러(PIC)를 통해 다중 인터럽트를 처리
    * 각 칩에 달린 핀으로 인터럽트의 우선순위를 정리해서 CPU에 알려줌
    * NMI(무시할 수 없는 인터럽트)까지 우선순위를 판별하지는 못함
* DMA(Direct Memory Access) 입출력
  * 프로그램, 인터럽트 기반은 반드시 CPU 가 필요하며 CPU의 부하로 발전
  * 이를 해결하기 위해 CPU를 거치지 않고도 I/O와 Memory가 상호작용하는 방식이 등장
    * 직접 메모리에 접근할 수 있는 입출력 기능 (DMA)
  * DMA 컨트롤러를 활용해 입출력 버스로 I/O의 정보를 관리
    * DMA 컨트롤러에서 직접 입출력 작업을 하며 작업이 끝나면 CPU에 인터럽트
* 사이클 스틸링
  * CPU의 시스템 버스는 동시 사용이 불가능 하다 (공유 불가능)
  * DMA 컨트롤러는 CPU 가 시스템 버스를 사용하지 않을 때 마다 슬쩍 사용
  * 혹은 CPU가 시스템 버스 사용을 양보하게 됨
  * 이 과정을 마치 훔친다 해서 사이클 스틸링
* PCIe(Peripheral Component Interconnect express)
  * PCI 입출력 버스의 발전된 형태
  * PCIe 버전에 따라 최대 속도가 달라질 수 있음
    * 버전이 증가함에 따라 레인당 최대 속도가 빨라짐
  * PCIe 버스가 여러 레인을 이용해 정보를 주고 받을 수 있음
    * PCIe version x lane count

## GPU (Graphic Processing Unit)

범용적인 목적의 GPU 사용 기술: GPGPU(General-Purpose computing on Graphic Process Units)
* CPU의 보조, 보조 프로세서
* 분할 작업에 좋음, 하나의 GPU의 코어 개수가 매우 많음
* 자체적 캐시, 메모리를 가지고 있음
