# RDBMS의 기본

## Key

> 키: 테이블 내 특정 레코드를 식별 할 수 있는 필드의 집합  
> (테이블 간 참조에도 사용된다.)

* 후보 키 (candidate key)
  * 한 레코드를 식별하기 위한 최소한의 필드로 구성 돼 **최소성**을 만족
  * 특정 레코드를 유일하게 식별하는 **유일성**을 만족
  * 두 필드 이상으로 구성된 후보키를 **복합키(Composite Key)** 라고 한다.
  * 최소성을 만족하지 않는 복합키(불필요한 필드 포함)를 **슈퍼키(Super Key)** 라고 한다.
* 기본 키 (Primary Key)
  * 한 테이블 당 하나만 존재할 수 있는 키, 후보키 중 대표하는 키
  * NULL이 될 수 없고, 중복된 값이 없어야하고 후보 키의 성질을 만족해야한다.
  * 기본 키가 아닌 후보 키를 **대체키(Alternate Key)** 라고 한다.
* 외래 키 (Foreign Key)
  * 다른 테이블의 기본 키를 참조하는 필드
    * 테이블의 관계를 표현 가능

## 테이블의 관계

* 일대일 대응 관계
  * 하나의 레코드가 다른 테이블의 레코드에 하나만 대응 될 수 있는 경우
* 일대다 대응 관계
  * 하나의 레코드가 다른 테이블의 여러 레코드와 대응 될 수 있는 경우
* 다대다 대응 관계
  * 한 테이블의 여러 레코드가 다른 테이블의 여러 레코드와 대응 되는 경우
  * 다대다 대응 관계는 중간 테이블을 수반한다.
    * TABLE A (N:1) TABLE B (1:N) TABLE C

## 무결성 제약 조건

> **무결성(Integrity)**: 일관되며 유효한 데이터 상태  
> 무결성 제약 조건: 데이터 베이스에 저장된 데이터의 일관성과 유효성을 유지하기 위한 조건

* **도메인 제약 조건 (Domain constraint)**
  * 테이블이 가질 수 있는 필드 타입과 범위에 대한 규칙 (엔티티의 각 속성에 대한 제약이다.)
    * 필드 데이터는 **원자 값(Atomic Value)** 를 가져야 한다.
    * 지정된 필드 타입을 준수해야 된다.
    * 값의 범위나 기본 값이 지정되었을 경우 지켜야한다.
    * NULL이 허용되지 않는다면 NULL 일 수 없다.
  * 원자 값: 더 이상 쪼갤 수 없는 데이터
    * JSON이나 배열 타입과 같은 정보가 비원자값이 될 수 있다.
* **키 제약 조건 (Key constraint)**
  * 레코드를 고유하게 식별할 수 있는 키로 지정된 필드는 중복된 값이 존재하면 안된다.
* **엔티티 무결성 제약 조건(Entity Integrity Constraint)**
  * 기본 키 제약 조건이라고도 한다.
    * 기본 키로 지정한 필드는 고유한 값이어야 한다.
    * NULL이 되어서는 안된다.
* **참조 무결성 제약 조건(referential integrity constraint)**
  * 외래키 제약 조건이라고도 한다.
    * 외래 키를 통해 다른 테이블을 참조 할 때, 일관성을 지키기 위한 제약 조건
    * 외래 키는 참조하는 테이블의 기본키 값이나 NULL을 가져야한다.

## 참조에 대한 동작 4가지

* **연산 제한 (restrict)**
  * 참조하는 테이블에서 수정이나 삭제가 발생할 경우 참조하고 있는 테이블에서 연산을 거부
* **기본 값 설정 (set default)**
  * 참조하는 테이블에서 삭제가 발생할 경우 참조하고 있는 테이블에서 기본 값을 사용
* **NULL 값 설정 (set null)**
  * 참조하는 테이블에서 삭제가 발생할 경우 참조하고 있는 테이블에서 null 값을 사용
* **연쇄 변경 (cascade)**
  * 참조하는 테이블의 상태에 따라 참조하고 있는 테이블의 상태가 변화됨
