# 코어와 멀티 코어

* CPU의 스레드 속도를 무작정 올리는데에는 한계가 있다. -> 발열
  * 코어와 스레드를 늘리는 해결책
* CPU 연산 속도는 코어 수에 비례하지는 않는다.
* 멀티코어: CPU 내부 장치가 여러개 구성된 것 

# 스레드 (해당 챕터는 하드웨어적 스레드 위주)

* 실행 흐름의 단위
  * 하드웨어적 스레드와 소프트웨어적 스레드가 구분 됨.
* 하드웨어적 스레드
  * 코어 하나 당 탑재된 스레드
  * 멀티스레드 프로세서(CPU) : 여러개의 스레드가 포함 
  * 인텔은 하이퍼스레딩이라는 기술을 사용 (멀티 스레딩과 동일)
  * 코어: 하드웨어 부품, 스레드: 실행 단위
  * 멀티스레드 프로세서: 하나의 코어로 여러개의 명령어를 동시에 실행할 수 있는 CPU
  * 논리 프로세서라고도 함 -> 프로그램 입장에서는 여러개의 CPU가 처리하는 것처럼 보임
* 소프트웨어적 스레드
  * 하나의 프로그램에서 독립적으로 실행되는 단위

# 명령어 병렬 처리 기법

* 멀티스레드를 지원하는 CPU를 만드는 방법

## 명령어 파이프 라이닝

* 파이프라인
  * 명령어 인출 (Instruction Fetch)
  * 명령어 해석 (Instruction Decode)
  * 명령어 실행 (Execute Instruction)
  * 결과 저장 (Write Back)
  * 즉, 스레드가 시간 별로 한 부분씩 처리하는 과정
    * 없다면, 하나의 명령어 처리가 다 끝나고 다음 명령어 처리를 가능
    * 해당 방법은 한 번에 여러개의 명령어 처리 가능

## 파이프 위험 (Pipeline Hazard)

* 실패하는 경우도 있다. 

### 데이터 위험 (Data Hazard)

* 데이터 의존성에 의해 발생
* 명령어 간 같은 레지스터를 참조 할 때, 순서대로 처리해야 됨.
* 무작정 같이 처리하려고 하면 발생하는 위험

### 제어 위험 (Control Hazard)

* 동시에 작업 중 명령어 A에서 분기 처리 됨 -> PC 변경
* 명령어 B와 C는 ?
* 분기 예측(branch predication)을 통해 예측하고 작업

### 구조적 위험 (Structural Hazard)

* 동시에 ALU와 같은 자원을 사용하려고 할 때, 동시성 문제
* 자원 위험이라고도 함

## 슈퍼 스칼라 (SuperScalar)

* 여러개의 명령어 파이프라인을 포함한 구조
* 지원하는 CPU를 슈퍼스칼라 프로세서(CPU)라고 함.
* Hazard가 더욱 잦기 떄문에 정교하게 설계되어야 함.

## 비순차적 명령어 처리 (OoOE; Out-of-order execution)

* 오늘날 CPU 향상에 크게 기여한 기법
* 명령어 파이프라이닝, 슈퍼스칼라 기법은 모두 순차적으로 처리
  * 비순차는 명렁어를 순차적으로 실행하지 않는다.
  * 위 두 방식에서 발생하는 데이터 위험을 해결 가능
  * A Regi가 필요해서 대기해야된다면, 대기하는 순간에 다른 명령어를 처리하는 방식
* 아무 명령어나 비순차적으로 처리하면 안된다.
  * 명령어 간 데이터 의존성을 명확히 식별하고 순서 교체를 판단하는 알고리즘이 필요하다.

# CISC와 RISC

* 명령어 병렬 처리 기법을 쉽게 하기 위한 명령어

## 명령어 집합 (Instruction Set)

* 명령어 집합 구조 (ISA) 라고도 함.
* CPU 마다 ISA가 다르다.
  * Intel CPU, Apple CPU
  * Windows exe 를 Mac 에서 실행할 수 없다.

## CISC (Complex Instruction Set Computer)

* 복잡한 명령어 집합을 활용하는 컴퓨터(CPU)
* 말 그대로, 가변 길이로 다양한 명령어 집합을 활용
* 장점 
  * 가변 길이라는 것은 필요한만큼 사용하기 때문에, 적은 명령어로도 처리가 가능
  * 메모리가 최대한 절약 됨
* 단점
  * 가변 길이기 때문에, 명령어 처리 시간이 일정하지 않음.
    * 데이터 하자드 등 고려하면 더 길어질 수도 있음.
    * 파이프 라이닝은 단계별 1클럭을 예상하고 설계 -> 설계와 다른 처리가 됨
  * 관측 결과, 자주 사용되는 명령어만 사용
    * 나머지는 그냥 파이프라인과 메모리 낭비만 하는 꼴

## RISC (Reduced Instruction Set Computer)

* CISC의 단점을 통해 알게 된 점
  * 파이프라이닝을 위해 명령어 길이, 수행 시간이 짧고 규격화 되어야 함.
    * 파이프 라인을 적극 활용해야 빠른 처리가 됨. CISC 는 파이프 라인을 활용하지 않는 부분이 많아짐
  * 자주 쓰이는 작고 빠른 명령어가 많아야 한다.
* RISC는 CISC의 단점을 극복하기 위해 등장한 것으로 고정 길이 명령어를 활용
  * 파이프라이닝 최적화
    * 메모리 접근을 load, store 두 개로 제한 (단순화)
    * load-store 구조라고도 함.
  * 레지스터의 적극 적인 활용
  * 사용가능한 명령어는 적으므로 많은 명령이 필요
    * 하나의 명령 당 명령어가 사용되기 때문
  * 고정 길이라서 1클럭 내외로 명령어를 수행 가능하도록 설계 가능
