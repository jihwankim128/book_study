## 저급언어

* 기계어 
  * 2진법 표현
  * 16진법 표현
* 어셈블리어

## 컴파일

* 소스 코드 전체가 저급 언어로 변환
  * 컴파일을 통해 수행
  * 목적 코드로 변환 됨
* 한 줄의 코드에 문제가 있으면 변환이 안됨

## 인터프리트

* 한줄 씩 저급 언어로 변환
* 한 줄의 코드에 문제가 있어도 변환이 됨
  * 문제가 있는 코드에서 오류 발생

## 컴파일과 인터프리트의 오해와 사실 

* 현대에는 결국 둘 다 사용된다.
  * 인터프리터의 한줄씩 변환하는 느린 변환 과정 해결을 위해 선 컴파일

## 링킹

* 목적 파일과 실행 파일은 다르다.
* 목적 파일은 여러 목적 파일로 구성된다.
* 여러 목적 파일 간 결합하기 위해 링킹을 한다.

## 오퍼랜드

* 오퍼랜드: 명령어를 사용할 데이터가 저장된 위치
* 0-주소, 1-주소, 2-주소, 3-주소 명령어
  * n-based

## 연산 코드

* 연산 코드: 연산을 수행할 명령어
    * 데이터 전송
    * 산술/논리 연산
    * 제어 흐름 변경
    * 입출력 제어

## 주소 지정 방식 (addressing mode)

* 유효주소 (effective address)
  * 데이터가 저장된 주소(위치)
* 즉시 주소 지정 방식 (immediate)
  * 오퍼랜드에 사용할 데이터를 직접 명시 (값)
  * 속도가 가장 빠름 (상수)
* 직접 주소 지정 방식 (direct)
  * 오퍼랜드에 유효주소를 직접 명시 (값의 위치)
  * 유효 주소의 제한이 있을 수 있음.
* 간접 주소 지정 방식 (indirect)
  * 유효 주소의 주소를 지정
  * 오퍼랜드의 짧은 길이 한계를 극복
  * 메모리 앞단을 간접 주소 지정으로 사용하면 됨.
  * 대신 메모리를 두 번 타야함. (유효주소 주소 -> 유효 주소(메모리) -> 값)
* 레지스터 주소 지정 방식 (register)
  * CPU 내부 레지스터의 유효 주소
  * 메모리를 거치지 않으므로 빠름
  * 직접 주소 지정 방식과 동일하게 값의 제한이 있을 수 있음
* 레지스터 간접 주소 지정 방식 (register indirect)
  * 레지스터가 메모리의 유효주소를 가지고 있음.
  * 오퍼랜드는 레지스터의 유효주소를 가르킴
  * 오퍼랜드 -> 레지스터 -> 메모리
